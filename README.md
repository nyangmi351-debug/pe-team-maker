# 🏃 체육 팀 편성 도우미

초·중등 체육 수업용 **실시간 팀 편성 웹앱**입니다.
학생들이 태블릿으로 자기평가/동료평가를 하면, 실력(1~4점 등급)과 성별 균형을 맞춘 팀이나 짝을 자동으로 만들어 줍니다.

- 교사: 4자리 교사 PIN 입력 → 명단 등록 → 평가 기준 입력 → 방 코드·QR 생성 → 실시간 현황 → 팀 편성 → 엑셀 저장
- 학생: QR 촬영 또는 6자리 방 코드 입력 → 이름 선택 → 점수 선택 → 제출 (회원가입 없음)

> 이 문서는 **개발을 처음 해 보는 분**을 기준으로 썼습니다. 순서대로 따라 하시면 됩니다.
> 대부분의 작업은 **웹 브라우저(크롬 권장)**만으로 끝납니다. 프로그램 설치가 필요한 부분은 '선택'으로 표시했습니다.

## 1. 전체 그림 이해하기

```
 [내 코드]  ──올리기──▶  [GitHub 저장소]  ──자동──▶  [GitHub Actions: 빌드]  ──자동──▶  [Firebase Hosting: 웹사이트]
                                                                                         │
                                         학생 태블릿 / 교사 PC  ◀──────── 접속 ─────────┘
                                                   │
                                                   └──▶ [Firebase Firestore(데이터)] + [Firebase Auth(로그인)]
```

| 이름 | 하는 일 | 비용 |
|---|---|---|
| **GitHub** | 코드를 보관하는 곳. 코드가 바뀌면 자동으로 웹사이트를 다시 만들어 줌(GitHub Actions) | 무료 |
| **Firebase Hosting** | 웹사이트 주소(`https://프로젝트ID.web.app`)를 제공 | 무료(Spark 요금제) |
| **Firestore** | 명단·평가 기준·점수 저장, 교사↔학생 화면 실시간 연결 | 무료 한도 안에서 충분 |
| **Authentication** | 익명 로그인 (회원가입 없이 자동 접속) | 무료 |

**준비물**: Google 계정(Firebase 콘솔용, 가능하면 **개인 Gmail** 권장 — 학교 계정은 8단계가 막혀 있을 수 있음), GitHub 계정(https://github.com 에서 무료 가입)

> ✏️ 앞으로 **고쳐야 할 파일은 딱 2개**입니다: `src/firebaseConfig.js`, `.firebaserc`

## 2. Firebase 프로젝트 만들기

1. https://console.firebase.google.com 접속 → Google 계정으로 로그인
2. **[Firebase 프로젝트 만들기]**(또는 '프로젝트 추가') 클릭
3. 프로젝트 이름 입력 (예: `pe-team-maker`)
   - 이름 아래 작게 보이는 **프로젝트 ID**(예: `pe-team-maker-1a2b3`)를 **메모해 두세요.** 나중에 계속 씁니다.
4. Google 애널리틱스는 **사용 안 함**으로 해도 됩니다 → **[프로젝트 만들기]** → 완료되면 **[계속]**

> 요금제는 기본값인 **Spark(무료)** 그대로 두면 됩니다. 결제 정보 입력은 필요 없습니다.

## 3. 웹 앱 등록하고 설정값 붙여넣기

1. 프로젝트 첫 화면(프로젝트 개요)에서 **`</>`(웹) 아이콘** 클릭
2. 앱 닉네임 입력 (예: `team-maker-web`)
   - "Firebase 호스팅도 설정" 체크박스는 **체크하지 않아도 됩니다** → **[앱 등록]**
3. 화면에 아래와 비슷한 코드가 나옵니다. `firebaseConfig = { ... }` 부분만 보면 됩니다.

   ```js
   const firebaseConfig = {
     apiKey: "AIzaSyB....",
     authDomain: "pe-team-maker-1a2b3.firebaseapp.com",
     projectId: "pe-team-maker-1a2b3",
     storageBucket: "pe-team-maker-1a2b3.firebasestorage.app",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcdef..."
   };
   ```

4. 이 프로젝트의 **`src/firebaseConfig.js`** 파일을 메모장(또는 VS Code)으로 열고, 같은 이름의 값 6개를 **그대로 바꿔 붙여 넣고** 저장합니다.
5. **`.firebaserc`** 파일을 열어 `여기에-프로젝트-ID-입력`을 내 **프로젝트 ID**로 바꿉니다.

   ```json
   { "projects": { "default": "pe-team-maker-1a2b3" } }
   ```

> 💡 이 설정값을 나중에 다시 보려면: 왼쪽 위 **톱니바퀴 ⚙️ → 프로젝트 설정 → 일반 탭 → 맨 아래 '내 앱'**
>
> 🔐 `apiKey`는 비밀번호가 아니라 "이 앱이 어느 Firebase 프로젝트를 쓰는지" 알려주는 공개 주소 같은 값이라 GitHub에 올라가도 괜찮습니다. 실제 데이터 보호는 5단계의 **보안 규칙**이 담당합니다.

> 📁 `.firebaserc`처럼 이름이 점(.)으로 시작하는 파일이 안 보이면:
> **Windows** 파일 탐색기 → 보기 → 표시 → '숨긴 항목' 체크 / **Mac** Finder에서 `Command + Shift + .`

## 4. 익명 로그인 켜기

이 앱은 교사·학생 모두 **회원가입 없이 자동 접속(익명 로그인)**합니다. 교사 화면은 **4자리 교사 PIN**으로 보호됩니다.

1. 왼쪽 메뉴에서 **Authentication** 클릭 (메뉴가 안 보이면 화면 위쪽 검색창에 `Authentication` 입력)
2. **[시작하기]** 클릭
3. **로그인 방법(Sign-in method)** 탭 → **익명(Anonymous)** 클릭 → **사용 설정** 켜기 → **[저장]**
4. '익명'이 '사용 설정됨'으로 보이면 완료 ✅ (Google 로그인은 켜지 않아도 됩니다)

## 5. Firestore 데이터베이스 만들기 + 보안 규칙

> ⚠️ **Realtime Database와 헷갈리지 마세요!** 메뉴에 'Realtime Database'도 있는데, 이 앱은 **Firestore Database**를 씁니다.
> Realtime Database 규칙 칸에 붙여 넣으면 `Line 1: Parse error`가 납니다.

### 5-1. 데이터베이스 만들기
1. 왼쪽 메뉴에서 **Firestore Database** 클릭 → **[데이터베이스 만들기]**
2. 버전(edition)을 고르라고 하면 **Standard**를 선택
3. 위치(Location): **`asia-northeast3 (Seoul)`** 선택 ← 한 번 정하면 바꿀 수 없으니 서울로!
4. 보안 규칙: **프로덕션 모드**로 시작 → **[만들기]**

### 5-2. 보안 규칙 붙여넣기 (중요!)
1. Firestore 화면 위쪽의 **규칙(Rules)** 탭 클릭 (편집기 1번 줄이 `rules_version = '2';`이면 맞게 찾은 것)
2. 편집기 안의 내용을 **전부 지우고**, 이 프로젝트의 **`firestore.rules`** 파일 내용을 **전부 복사해서 붙여 넣기**
3. **[게시(Publish)]** 클릭

> 이 규칙이 하는 일
> - 교사 자료(명단·템플릿·평가 기록)는 **교사 PIN을 입력한 기기**에서만 읽고 쓸 수 있습니다.
> - 교사 PIN 자체는 아무도(교사 본인도) 데이터베이스에서 읽을 수 없게 숨겨집니다.
> - 학생은 방 정보만 보고, **자기 평가를 딱 1번만 제출**할 수 있습니다.
> - 학생이 낸 점수는 **교사만** 볼 수 있습니다. (다른 학생 점수는 학생 화면에 노출되지 않음)
>
> ⚠️ 규칙을 게시하지 않으면 앱에서 "권한 없음(permission-denied)" 오류가 납니다.

## 6. Hosting 시작하기

1. 왼쪽 메뉴에서 **Hosting** 클릭 → **[시작하기]**
2. 'Firebase CLI 설치', '프로젝트 초기화', '배포' 안내가 차례로 나오는데, **명령어는 실행하지 않고 [다음] → [다음] → [콘솔로 이동]**만 누르면 됩니다.
   (실제 배포는 GitHub Actions가 대신 해 줍니다.)
3. Hosting 화면에 `프로젝트ID.web.app` 주소가 보이면 준비 완료 ✅

## 7. GitHub 저장소 만들고 코드 올리기

### 7-1. 저장소 만들기
1. https://github.com 로그인 → 오른쪽 위 **`+` → New repository**
2. Repository name: `pe-team-maker` (원하는 이름)
3. **Private**(비공개) 추천 → 나머지는 건드리지 말고 **[Create repository]**

### 7-2. 파일 올리기 (브라우저만으로)
1. 받은 압축 파일을 풀고, **3단계에서 두 파일을 수정했는지** 다시 확인합니다.
2. 방금 만든 저장소 화면에서 **"uploading an existing file"** 링크 클릭
3. 압축을 푼 폴더 **안의 내용물 전체**(`src`, `public`, `.github`, `package.json`, `firebase.json`, `.firebaserc` …)를 선택해서 브라우저 창으로 **끌어다 놓기**
   - ⚠️ 바깥 폴더(`pe-team-maker`) 자체가 아니라 **그 안의 파일·폴더들**을 끌어다 놓아야 합니다.
   - ⚠️ 숨김 폴더 **`.github`**와 숨김 파일 **`.firebaserc`, `.gitignore`**도 꼭 포함하세요 (3단계 '숨긴 항목 보기' 참고).
4. 아래 **[Commit changes]** 클릭
5. 저장소 첫 화면에 `.github`, `src`, `package.json` 등이 보이면 성공 ✅

> 이 순간 GitHub Actions가 자동으로 배포를 시도하지만, 아직 **8단계의 열쇠**가 없어서 ❌ 실패로 표시됩니다. 정상이니 걱정하지 마세요.
>
> 💡 파일을 자주 고칠 계획이면 **GitHub Desktop**(https://desktop.github.com) 프로그램을 쓰면 더 편합니다.

## 8. 자동 배포용 열쇠(서비스 계정) 만들기

GitHub가 내 Firebase에 웹사이트를 올리려면 **'배포 전용 열쇠'(서비스 계정 키)**가 필요합니다.

### 8-1. 서비스 계정 만들기 (Google Cloud 콘솔)
1. 주소창에 아래 주소를 입력합니다. (`내프로젝트ID` 부분을 바꾸세요)
   ```
   https://console.cloud.google.com/iam-admin/serviceaccounts?project=내프로젝트ID
   ```
   (Firebase와 같은 Google 계정으로 로그인되어 있어야 합니다)
2. 위쪽 **[+ 서비스 계정 만들기]** 클릭
3. 서비스 계정 이름: `github-deploy` → **[만들고 계속하기]**
4. **역할 선택**에서 아래 4개를 하나씩 추가합니다. (검색창에 이름을 입력하면 찾기 쉽습니다. **[+ 다른 역할 추가]**로 추가)

   | 역할 이름 (한국어 화면) | 영어 이름 |
   |---|---|
   | Firebase 호스팅 관리자 | Firebase Hosting Admin |
   | API 키 뷰어 | API Keys Viewer |
   | Firebase 인증 관리자 | Firebase Authentication Admin |
   | Cloud Run 뷰어 | Cloud Run Viewer |

5. **[계속]** → **[완료]**

### 8-2. 키(JSON 파일) 내려받기
1. 목록에 생긴 `github-deploy@...` 이메일을 클릭
2. 위쪽 **키(Keys)** 탭 → **[키 추가] → [새 키 만들기]** → **JSON** 선택 → **[만들기]**
3. `.json` 파일이 컴퓨터에 다운로드됩니다. 메모장으로 열어 **내용 전체를 복사**합니다. (`{`로 시작해서 `}`로 끝남)

### 8-3. GitHub에 열쇠 등록하기
1. GitHub 저장소 → **Settings**(톱니바퀴) → 왼쪽 **Secrets and variables → Actions**
2. **[New repository secret]** 클릭
3. Name: **`FIREBASE_SERVICE_ACCOUNT`** (철자 그대로!)
4. Secret: 방금 복사한 JSON 내용 **전체 붙여 넣기** → **[Add secret]**
5. 등록이 끝나면 **내려받은 JSON 파일은 컴퓨터에서 삭제**하세요. (절대 저장소에 올리면 안 됩니다)

> 🏫 "조직 정책에 의해 키 생성이 차단됨" 메시지가 나오면 학교(Google Workspace) 계정이라 막힌 것입니다. **개인 Gmail 계정**으로 2단계부터 Firebase 프로젝트를 만드세요.

## 9. 배포 확인하기

1. GitHub 저장소 위쪽 **Actions** 탭 클릭
2. 왼쪽에서 **Firebase Hosting 자동 배포** 선택 → 오른쪽 **[Run workflow] → [Run workflow]** 클릭
   (7단계에서 실패했던 것을 다시 실행하는 것입니다. 이후로는 코드를 올릴 때마다 자동 실행)
3. 2~3분 기다리면 노란 점 🟡 → 초록 체크 ✅ 로 바뀝니다.
4. 브라우저에서 **`https://내프로젝트ID.web.app`** 접속 → 앱 첫 화면이 보이면 완성! 🎉

> ❌ 빨간 X가 뜨면 해당 항목을 클릭해 빨간 글씨를 확인하고 [12. 문제 해결](#12-문제-해결-자주-묻는-질문)을 보세요.

## 10. 수업에서 사용하는 방법

### 교사 (PC, 전자칠판)
1. `https://내프로젝트ID.web.app` → **선생님**
   - **처음 1번**: 교사 PIN(숫자 4자리)을 정합니다. 배포가 끝나면 **학생들보다 먼저** 들어가서 만들어 두세요.
   - 그다음부터: PIN을 입력하면 그 기기가 '교사 기기'로 등록되어, **[🔒 잠그기]**를 누르기 전까지 다시 묻지 않습니다.
   - 교사 PC를 학생과 같이 쓴다면 수업이 끝날 때 **[🔒 잠그기]**를 눌러 두세요. PIN은 화면 위 **[PIN 바꾸기]**로 바꿀 수 있습니다.
2. **새 평가 시작**
   - **1단계 명단**: `이름 성별` 형식으로 한 줄에 한 명 입력 (예: `다온 여`). 같은 이름은 자동으로 `민준1`, `민준2`로 구분됩니다. **[명단 저장]**하면 다음 수업 때 불러올 수 있어요.
   - **2단계 평가**: 제목과 1~4점 기준 입력(또는 템플릿 불러오기) → 평가 방식(개별/동료) 선택 → **[평가 방 만들기]**
3. **실시간 현황**: 방 코드와 QR이 생깁니다. **[QR 크게 띄우기]**로 칠판에 띄우세요.
   - 학생 카드가 초록색(제출 완료)으로 바뀌는 것을 실시간으로 볼 수 있습니다.
   - 결석·기기 오류 학생: 카드를 눌러 **점수 직접 입력** 또는 **결석 처리**
   - 학생이 이름을 잘못 눌러 제출했다면: 카드를 눌러 **제출 취소(다시 하기)**
4. 모두 끝나면 **"모든 학생 평가가 완료되었습니다."** → 평가 기록이 자동 저장되고, 팀 편성 버튼 3개가 나타납니다.
5. **팀 편성 화면**
   - **학생 반으로 나누기 / 남자팀·여자팀 / 짝 만들기** 중 선택 (바꾸면 바로 다시 편성)
   - 학생 이름을 **끌어다 놓아** 팀원 교체 (다른 학생 위 = 맞바꾸기, 팀 빈 곳 = 이동). 평균·에이스 수가 즉시 다시 계산됩니다.
   - 팀 색 버튼을 눌러 **조끼 색 변경**, ★을 눌러 **주장 변경**
   - **📺 학생 공개 모드**: 점수는 숨기고 팀 색·이름·주장만 크게 표시 (칠판 투사용)
   - **📥 엑셀 다운로드**: `날짜_평가제목_팀편성결과.xlsx`

### 다음 수업에서 (재평가 생략)
대시보드 → **이전 평가 기록** → **[이 기록으로 팀 편성]** → 오늘 결석한 학생만 **[참여 학생]**에서 빼고 바로 편성

### 학생 (1인 1태블릿)
QR 촬영 또는 `https://내프로젝트ID.web.app/join` 에서 6자리 방 코드 입력 → 내 이름 터치 → 점수 선택 → 제출

## 12. 문제 해결 (자주 묻는 질문)

| 증상 | 원인과 해결 |
|---|---|
| 첫 화면 위에 **"Firebase 설정이 아직 안 되어 있어요"** | `src/firebaseConfig.js`에 3단계 값을 붙여 넣지 않았습니다. 수정 후 다시 커밋하세요. |
| Actions 오류: `Input required and not supplied: firebaseServiceAccount` | GitHub Secret 이름이 `FIREBASE_SERVICE_ACCOUNT`와 정확히 같은지 확인 (8-3단계) |
| Actions 오류: `403`, `permission`, `does not have permission` | 8-1단계의 역할 4개가 모두 추가되었는지 확인. Google Cloud 콘솔 → IAM 메뉴에서 `github-deploy` 계정 옆 연필 아이콘으로 역할 추가 가능 |
| Actions 오류: `No project active` / `Invalid project id` | `.firebaserc`의 프로젝트 ID를 확인 (3단계 5번) |
| Actions 오류에 `site`, `Hosting` 관련 내용이 보임 | 6단계(Hosting 시작하기)를 진행했는지 확인하세요. |
| Actions 오류: `npm install` 단계 실패 | 일시적인 네트워크 문제일 수 있어요. Actions에서 **Re-run jobs**로 다시 실행 |
| "접속에 실패했어요" / 학생 화면 "입장 오류" | 4단계에서 **익명** 로그인을 켰는지 확인 |
| 규칙 저장 시 `Line 1: Parse error` | **Realtime Database** 규칙 칸에 넣은 것입니다. **Firestore Database** → 규칙 탭에 넣으세요. |
| 교사 PIN을 잊어버림 | Firebase 콘솔 → Firestore Database → 데이터 탭 → `config` 컬렉션 → 문서 `teacher`와 `status`를 **삭제** → 앱에서 '선생님'을 누르면 PIN을 새로 만들 수 있어요. (명단·기록은 그대로 남음) |
| 처음 들어갔는데 PIN 만들기 대신 PIN 입력 화면이 나옴 | 이미 누군가 PIN을 만든 것입니다. 본인이 만든 게 아니라면 위의 'PIN을 잊어버림' 방법으로 지우고 다시 만드세요. |
| "권한 없음", `Missing or insufficient permissions` | 5-2단계 보안 규칙을 **게시**했는지 확인 |
| 학생이 다른 친구 이름으로 잘못 제출함 | 교사 현황 화면에서 그 친구 카드 클릭 → **제출 취소(다시 하기)** |
| 새 버전을 배포했는데 예전 화면이 보임 | 브라우저 새로고침(Ctrl+F5) |

## 13. (선택) 내 컴퓨터에서 실행해 보기

배포 전에 미리 확인하고 싶을 때만 필요합니다.

2. 프로젝트 폴더에서 터미널(Windows: 폴더 주소창에 `cmd` 입력 후 Enter) 열기

### 교사 PIN 보안 수준
4자리 PIN은 교실에서 학생이 교사 화면에 들어오는 것을 막는 정도의 보호입니다. 학생 이름과 체육 점수 외의 민감한 개인정보는 저장하지 마세요. 정해진 PIN은 데이터베이스에서 읽을 수 없고, 보안 규칙이 입력한 PIN과 비교만 합니다.

### 팀 편성 원리
- **층화 배분(최우선)**: 4점 → 3점 → 2점 → 1점 순서로, 각 등급 학생을 팀마다 같은 수만큼 나눕니다. 그래서 4점(에이스) 2명이 한 팀에 몰리지 않습니다. 동료평가의 소수점 점수는 반올림한 등급을 쓰고, 같은 등급 안에서는 점수 높은 순으로 배분합니다.
- **스네이크 드래프트 효과**: 같은 조건이면 점수 합이 낮은 팀이 다음 학생을 먼저 받습니다.
- **성비**: 팀별 남녀 수를 맞추고, 2팀 홀수 인원(예: 25명 → 12 vs 13)이면 **인원이 적은 팀에 남학생 1명을 더** 배치합니다. (등급 균형을 동시에 맞출 수 없는 드문 경우에는 등급 균형을 우선)
- **마무리 다듬기**: 두 학생을 맞바꿔 보며 등급·성비·평균 점수 차이가 더 줄어드는 경우에만 교환합니다.
- **짝 만들기**: 점수가 비슷한 학생끼리 짝 (다른 성별 옵션은 남녀 점수 차의 합이 가장 작아지도록 매칭). 홀수면 남는 1명은 평균이 가장 비슷한 짝에 들어가 3인 1조가 됩니다.
- **동료평가 순환 배정**: 학생을 무작위 원형으로 세우고 각자 다음 N명(3~5명)을 평가 → 모든 학생이 **정확히 N번** 평가받습니다.
- **주장**: 동료평가 시 팀 안에서 리더십 득표가 가장 많은 학생(동점이면 점수 높은 학생).
- **[다시 편성하기]**를 누를 때마다 같은 점수 학생들의 순서가 무작위로 섞여 다른 조합이 나옵니다.
